---
name: 公開ビルドのセキュリティ検査
description: 公開時のビルドログに詳細が出ないセキュリティ検査失敗の切り分け方
---

公開ビルドが依存関係のインストールやアプリのビルドを完了したあと、詳細なエラーを出さず二度目の Security Scan で停止することがある。公開ログだけで原因を推測せず、OSV ベースの依存監査でパッケージ名・バージョン・修正版を確認し、修正後に frozen install と本番ビルドを再実行する。

**Why:** 公開ビルドログではセキュリティ検査の個別 finding が省略される一方、通常の `pnpm audit` やローカルビルドだけでは検出条件が一致しないことがある。

**How to apply:** まず直近の失敗ビルドと成功ビルドのフェーズを比較し、アプリ起動やヘルスチェックの調査より先に依存監査を行う。トランジティブ依存は親を更新し、親に修正版がない場合だけ影響範囲を限定した override を使う。依存検査・アプリビルド完了後に `Repl layer` 作成でログが途切れ、成功ビルドだけが image manifest 作成へ進む場合は、コード変更より先に公開の再試行または基盤障害として扱う。
