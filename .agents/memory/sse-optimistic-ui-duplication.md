# SSEストリーミング + 楽観的UIの二重表示

「メッセージが二度送信される」というユーザー報告の実体は、二重POSTではなく**二重表示**だった（DBには1件しか保存されていなかった）。

**Why:** ストリーミング完了時に `invalidateQueries` で会話を再取得すると、サーバー保存済みメッセージと、まだクリアされていない楽観的ユーザーメッセージ／ストリーミング中の吹き出しの両方が同時に描画される瞬間ができる。クリアを先にすると一瞬メッセージが消えてチラつく。

**How to apply:**
1. 完了コールバックで `await queryClient.invalidateQueries(...)` の完了を待ってからストリーミング状態・楽観的メッセージをクリアする。
2. 保険として描画側でも重複ガードを入れる — サーバーメッセージに同一内容がある場合は楽観的メッセージ／ストリーミング吹き出しをスキップ。
3. 二重送信対策自体も必要: 送信ハンドラの実行中ガード（refフラグ、await完了まで保持）、IME確定Enterは `e.nativeEvent.isComposing` で無視、SSEの `done` イベントとストリーム終端の両方から呼ばれる完了処理はフラグで1回に限定。

デバッグ時の教訓: 「二重送信」報告はまずDBを見て、送信が2件か表示が2件かを切り分けること。
